# agentAPP 知识库建议稿

这份知识库是按当前 `agentAPP` 的业务整理的，适合直接作为 `manual` / `faq` 类型的知识源导入，也可以拆成多条 `inform` 同步内容。

## 设计原则

- 只写项目里真实存在的业务名词：通知、请假、员工、部门、图片上传、首页统计、智能助手。
- 每条知识尽量回答一个明确问题，方便向量检索命中。
- 公开知识和部门知识分开写，避免权限混乱。
- 长文档要拆短，标题尽量具体，不要只写“使用说明”。

## 推荐分类

| 分类 | 建议 `source_type` | 可见范围 | 适用场景 |
| --- | --- | --- | --- |
| 系统总览 | `manual` | `is_public=true` | 新员工入门、快速了解系统 |
| 账号与登录 | `faq` | `is_public=true` | 登录、密码重置、激活 |
| 员工与部门 | `manual` | `is_public=true` 或指定部门 | 员工资料、部门管理、负责人职责 |
| 通知管理 | `faq` / `inform` | 按部门控制 | 发布通知、阅读记录、可见范围 |
| 请假/考勤 | `manual` / `faq` | 按部门控制 | 请假类型、审批流程、状态说明 |
| 图片上传 | `faq` | `is_public=true` | 编辑器上传图片、附件说明 |
| 智能助手使用 | `manual` | `is_public=true` | 怎样问、怎样限定知识源、怎样反馈 |
| 运维说明 | `manual` | 管理员可见 | 索引失败、重建索引、同步通知 |

## 推荐条目清单

### 1. OA系统快速开始
- `source_type`: `manual`
- `is_public`: `true`
- 目标问题：这个系统能做什么，先从哪里开始用。
- 建议内容：
  - 本系统包含登录、员工管理、部门管理、通知、请假、图片上传、首页统计和智能助手。
  - 进入首页后先看通知、请假和最近动态。
  - 在 `智能助手` 页面可以按知识库提问，也可以限定某些知识源。

### 2. 登录与密码重置
- `source_type`: `faq`
- `is_public`: `true`
- 目标问题：怎么登录、忘记密码怎么办、账号激活怎么处理。
- 建议内容：
  - 使用邮箱和密码登录。
  - 如果管理员创建了员工账号，首次使用前需要完成激活。
  - 密码重置后，建议再次确认邮箱是否可用。

### 3. 员工新增与激活
- `source_type`: `manual`
- `is_public`: `true`
- 目标问题：管理员怎么新增员工，员工为什么进不去系统。
- 建议内容：
  - 员工包含姓名、邮箱、手机号、部门等基础信息。
  - 新建员工后通常要发送激活流程。
  - 员工是否可用，和账号状态、部门归属有关。

### 4. 部门管理说明
- `source_type`: `manual`
- `is_public`: `true`
- 目标问题：部门有哪些字段，负责人是谁，谁能看见哪些内容。
- 建议内容：
  - 部门包括名称、简介、负责人、管理人。
  - 部门会影响通知可见范围、员工归属和知识库权限。

### 5. 通知发布规范
- `source_type`: `faq`
- `is_public`: `true`
- 目标问题：通知怎么发，全员和部门通知怎么区分。
- 建议内容：
  - `department_ids` 里包含 `0` 时，表示全员可见。
  - 不包含 `0` 时，通知只对指定部门可见。
  - 通知正文尽量写清时间、对象、动作、截止时间。

### 6. 通知阅读与已读规则
- `source_type`: `inform`
- `is_public`: `true`
- 目标问题：什么叫已读，为什么会显示阅读量。
- 建议内容：
  - 通知阅读记录会单独保存。
  - 同一用户对同一通知只记录一次阅读。
  - 可以作为后续统计和追踪依据。

### 7. 请假申请流程
- `source_type`: `manual`
- `is_public`: `false`
- 适用部门：人事、直属部门、审批角色所在部门
- 目标问题：怎么请假，状态分别是什么意思。
- 建议内容：
  - 请假包含标题、请假内容、请假类型、开始日期、结束日期。
  - 状态一般分为审批中、通过、拒绝。
  - 审批结果要写明原因，避免重复沟通。

### 8. 请假审批规则
- `source_type`: `faq`
- `is_public`: `false`
- 适用部门：部门负责人、审批人
- 目标问题：谁来审批，什么时候能改状态。
- 建议内容：
  - 审批人通常由系统规则或部门关系决定。
  - 只有当前审批人可以修改审批状态和回复内容。
  - 审批通过后再进入后续流程。

### 9. 首页统计口径
- `source_type`: `manual`
- `is_public`: `true`
- 目标问题：首页的通知、请假、部门员工数怎么算。
- 建议内容：
  - 首页会展示最新通知、最新请假和部门人数。
  - 统计结果可能存在缓存，刷新不会立刻变化。
  - 部门人数按当前归属部门统计。

### 10. 图片上传说明
- `source_type`: `faq`
- `is_public`: `true`
- 目标问题：编辑器里的图片怎么上传，返回什么地址。
- 建议内容：
  - 图片上传后会返回可直接插入编辑器的 URL。
  - 适合通知正文、知识条目正文、内容编辑场景。

### 11. 智能助手怎么提问
- `source_type`: `manual`
- `is_public`: `true`
- 目标问题：怎么让助手回答更准。
- 建议内容：
  - 问题尽量具体，比如“如何发布全员通知”而不是“怎么用系统”。
  - 可以先限定知识源，再发问。
  - 回答末尾会带引用来源，优先参考引用内容。

### 12. 知识库维护规范
- `source_type`: `manual`
- `is_public`: `false`
- 适用部门：管理员、知识库维护人
- 目标问题：知识库怎么更新，什么内容适合入库。
- 建议内容：
  - 适合入库的内容：制度、流程、操作手册、常见问题、变更通知。
  - 不适合入库的内容：临时闲聊、重复口号、空标题。
  - 一个知识源只讲一个主题，标题要能直接看懂。

## 可直接导入的样例正文

### OA系统快速开始

本系统是公司的 OA 助手平台，主要用于通知发布、员工与部门管理、请假审批、图片上传和知识问答。

进入系统后，建议先查看以下几个区域：

1. 首页：查看最新通知、最新请假和部门人数。
2. 通知：查看自己可见的通知，确认是否已读。
3. 请假：发起请假申请，查看审批状态。
4. 员工与部门：查看组织结构和人员归属。
5. 智能助手：针对系统问题、制度问题、流程问题进行检索问答。

如果你不确定某个功能在哪里，可以直接问智能助手，例如：

- 如何发布全员通知？
- 请假审批状态有哪些？
- 员工新增后为什么不能登录？

### 通知发布规范

通知是系统中最常用的信息分发方式。发布通知时，标题要短，正文要清晰，建议包含时间、对象、动作和截止时间。

可见范围规则如下：

- `department_ids` 包含 `0`：表示全员可见。
- 只传部门 id：表示仅指定部门可见。
- 管理员在后台同步通知后，助手可以把通知内容作为知识来源进行问答。

为了让知识库更好检索，建议通知正文采用固定结构：

1. 事项说明
2. 适用范围
3. 时间要求
4. 联系人
5. 补充说明

### 请假申请流程

请假单包含标题、请假内容、请假类型、开始日期、结束日期、发起人、审批人和审批状态。

状态说明：

- 审批中：等待审批。
- 通过：审批通过，可进入后续处理。
- 拒绝：审批未通过，需要补充说明或重新申请。

建议在知识库里补充两类内容：

- 申请规则：哪些假期可以申请，审批顺序是什么。
- 常见问题：日期冲突、审批人缺失、状态长时间不变怎么办。

### 智能助手使用说明

智能助手不是泛聊天机器人，它主要根据系统内的知识库回答问题。

提问建议：

- 问一个具体问题。
- 需要时手动限定知识源。
- 遇到流程问题时，优先问“怎么做”，不要只问“是什么”。

如果助手回答不完整，可以继续追问：

- 这个流程对应哪个角色？
- 哪些部门能看到？
- 有没有官方说明？

## 推荐的 metadata 结构

导入时建议给每条知识加上这些 metadata：

```json
{
  "tags": ["通知", "全员", "发布规范"],
  "summary": "说明全员通知的发布规则与可见范围",
  "audience": ["全体员工"],
  "scene": "通知发布"
}
```

3. 请假申请与审批流程
4. 员工、部门、权限说明
